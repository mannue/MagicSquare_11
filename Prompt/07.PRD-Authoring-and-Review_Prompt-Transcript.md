# MagicSquare — PRD Authoring and Review Prompt Transcript

아래는 본 세션에서 진행된 주요 사용자 요청과 AI 응답의 대화형 기록이다.

---

## [User #1]
PRD를 바로 작성하지 말고,  
먼저 PRD 작성 참고 문서를 분석하고,  
각 문서 내용을 PRD 섹션에 매핑해 달라고 요청.

## [Assistant #1]
- `Prompt`, `Report`, `.cursor/rules`, `.cursorrules`, `.cursor/agents` 문서를 수집/분석.
- 문서별 핵심 내용과 PRD 섹션 매핑표 제공.
- 우선 반영 소스(필수/보강/운영 부록)를 구분해 제안.

---

## [User #2]
PRD를 만들기 위한 프롬프트를 어떻게 만들면 되는지 요청.

## [Assistant #2]
- PRD 프롬프트 설계 방법(역할 고정, 입력 문서 강제, 출력 구조 고정, 품질 규칙, 산출 형식) 5단계 제시.
- 바로 실행 가능한 PRD 생성 프롬프트 템플릿 제공.

---

## [User #3]
제공된 가이드/템플릿을 기반으로 실제 PRD 작성 지시문 제공.

## [Assistant #3]
- 지정 구조(Overview~Appendix)에 따라 PRD 본문을 Markdown으로 작성.
- Functional/Non-Functional 분리, In/Out Scope, KPI, Validation Plan, Self-check, Next Actions 포함.

---

## [User #4]
장문 PRD 프롬프트를 참고해 현재 프로젝트 환경에 맞게 수정 요청.

## [Assistant #4]
- 저장소 실제 문서명과 규칙 파일 기준으로 프롬프트 보정.
- 문서 우선순위, 충돌 처리(`Decision Needed`), Source/Traceability 강제 조건 포함.
- 바로 복붙 가능한 최종 프롬프트 제공.

---

## [User #5]
수정본을 다시 제시하며, 더 완성도 높은 최종본 요청.

## [Assistant #5]
- 실행 안정성 관점 보강:
  - 문서 접근 실패 시 처리 규칙
  - FR/BR/NFR의 Source 명시
  - Traceability Matrix Source 컬럼 추가
  - 충돌/미확정 항목의 분리 규칙 강화
- 최종 프롬프트 재제공.

## [User #7]
방금 작성한 PRD를 다음 기준으로 리뷰 요청(수정 금지, 문제/개선안만):
1) 모든 FR의 테스트 가능한 AC 존재 여부  
2) AC의 Traceability 연결 여부  
3) Boundary/Domain 책임 혼합 여부  
4) 오류 정책 미정 여부  
5) small-first / reverse 데이터 구분 여부  
6) 1-index/row-major 누락 여부  
7) 코드/테스트 코드 포함 여부

## [Assistant #7]
- `docs/PRD_MagicSquare.md` 전수 검토 후 이슈 보고:
  - 실패 정책 본문 vs Decision Needed 간 모순
  - unsolvable 실패 AC의 Traceability Matrix 연결 누락
  - 오류 코드 체계 일부 불일치
  - FR-05의 레이어 책임 표기 혼합
  - small-first/reverse 데이터 구분 기준 구체성 부족
- 기준별 충족/미충족 판정과 개선안 제시.
